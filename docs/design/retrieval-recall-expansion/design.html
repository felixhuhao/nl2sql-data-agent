Retrieval Recall Expansion + Confidence-Triggered Fallback

Lane: full (lightweight)   Status: Done

Digest

Change: Add deterministic graph expansion of recalled tables + a hybrid coverage score that triggers full-schema fallback on low confidence (not just empty recall).

Decisions (decision — why — rejected):

  • Hybrid coverage score (match strength × structural joinability) — a query can have strong hits yet no joinable subgraph, or the reverse; either signal alone misses a real failure. Rejected: recall-strength-only, structural-only.
  • 1-hop, fanout-gated, bidirectional, capped expansion — recovers fact↔dim both directions on a star schema while preserving the ~75% context reduction. Rejected: transitive (pulls whole star, redundant vs fallback), fact-anchored (one-directional).
  • Two-stage recovery — low → expand → re-score → full-schema only if still low; cheap deterministic recovery before paying full-schema cost. Rejected: direct fallback.
  • Size-capped full-schema fallback — fall back only when full schema fits a budget; else keep expanded focused context (honours the Death of Schema Linking? caveat).
  • Calibrated defaults on, rollback flags retained — threshold 0.7 showed 0/61 high-confidence regressions; operators can still disable expansion/fallback for parity checks or emergency rollback.

Risks / watch:

  • Weights & threshold are eval-calibrated, not derivable a priori.
  • Expansion must respect analysis-space scoping or it breaks the shared governance model.
  • Must be a no-op (not a crash) on datasources with no relationships.

Calibrated defaults:

  • w_strength=0.5, w_struct=0.5, threshold 0.7, max expansion tables 3, full-schema budget 120000. Known follow-up: missing_dimension scorer behavior.

Drill down: full design below · files in docs/design/retrieval-recall-expansion/.

1. Problem / context

Focused retrieval recalls tables/columns/metrics/aliases via rule + optional vector recall; today the only safety net is: empty recall → full-schema fallback. The real gap (schema-linking research) is non-empty but structurally incomplete recall — some tables surfaced, a needed dimension or join path missed. That context is irrevocably lost and the LLM generates over an incomplete schema with no signal anything was wrong. Highest-leverage accuracy failure, currently invisible.

2. Goals

In scope: deterministic graph expansion; hybrid coverage score with high|low band; two-stage recovery control flow; telemetry (score/band, expanded, fallback_used); eval cases for incomplete recall; feature flags default on after calibration with rollback support.

Out of scope: any LLM-based schema linking (separate later item); changing rule/vector scoring; multi-hop expansion; changing SQL Guard / execution / semantic guard.

3. Proposed approach

# Stage 1 — raw recall
raw = retriever(question, datasource)

# Stage 2 — merge carried conversation assets (as today)
result = merge_prior_assets_into_retrieval(raw, conversation_context)

# INVARIANT: empty recall always → full schema (independent of flags/budget)
if is_empty(result):
    state.retrieval_coverage = coverage_empty(fallback_used=True)
    return full_schema_context(datasource)

coverage = score_coverage(result, datasource)           # hybrid, on merged set

# Stage 3 — deterministic expansion (recovery on low confidence)
if coverage.band == "low" and EXPANSION_ENABLED:
    result   = expand_via_graph(result, datasource)
    coverage = score_coverage(result, datasource)       # re-score on expanded set

# Stage 4 — NEW low-confidence fallback (gated + size-budgeted)
if coverage.band == "low" and RETRIEVAL_FALLBACK_MODE == "on" and full_schema_fits_budget(datasource):
    coverage.fallback_used = True
    state.retrieval_coverage = coverage
    return full_schema_context(datasource)

# Stage 5 — render from the SAME set coverage was computed on
state.retrieval_coverage = coverage
return build_focused_context_from_retrieval(result, datasource)

High-confidence common case is unchanged — no expansion, no extra cost. Canonical stages raw→merged→expanded→rendered mean coverage/telemetry always describe the exact rendered set. Empty recall is an unconditional invariant → full schema, matching today (no regression). Fact-role = FK-topology heuristic (source of ≥FACT_MIN_DIM_EDGES many_to_one edges), no metadata column or naming dependency.

4. Key decisions — alternatives & rationale

D1 — Coverage signal: Hybrid (chosen)

OptionProsCons
Hybrid (chosen)Catches strong-but-disconnected AND weak-but-connected recalls; models the lost-context risk directly.Two things to calibrate.
Recall strength onlySimplest; reuses existing scores.Blind to structure — passes disconnected recall to the LLM.
Structural onlyEncodes joinability directly.Misses weak/ambiguous recall where the right tables weren't found.

D2 — Expansion depth: 1-hop bidirectional (chosen)

OptionProsCons
1-hop bidirectional (chosen)Recovers fact↔dim both directions; preserves context reduction; composes with fallback.Won't self-recover a 2-hop gap — fallback covers it.
Fact-anchoredTightest; star-shaped.One-directional; misses dim-recalled-but-not-fact recovery.
TransitiveHighest recall.Pulls the whole star; erodes reduction; redundant given fallback.

D3 — Fallback flow: Two-stage recovery (chosen)

Low → expand → re-score → full schema only if still low. Rejected direct fallback: simpler flow but more full-schema hits → higher cost/hallucination, wasting cheap recovery.

D4 — Size-capped full-schema fallback (chosen)

Fall back only when full schema fits a budget; else keep expanded focused context. Full schema rivals schema-linking only when it fits.

D5 — Enable calibrated defaults with rollback flags (chosen)

Initial implementation shipped dark behind flags for eval calibration. After closeout calibration at threshold 0.7 showed 0/61 high-confidence regressions, the product default is enabled while keeping RETRIEVAL_EXPANSION_ENABLED=false and RETRIEVAL_FALLBACK_MODE=off available for parity tests and emergency rollback.

5. Altitude — deferred to implementation

  • Function/dataclass names; RetrievalCoverage as dataclass vs typed dict.
  • SSE payload field naming/placement.
  • Line-level traversal code; match_strength normalization formula.
  • Calibrated values: w_strength=0.5, w_struct=0.5, threshold 0.7, MAX_TABLES=3, full-schema budget 120000.

6. Open questions

  • missing_dimension recovery remains a scorer follow-up: fact-only metric intent currently scores structurally high before expansion.
  • Whether medium fanout counts fractionally vs fully against the cap → default full; revisit if calibration shows over-pruning.
