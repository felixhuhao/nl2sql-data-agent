1. Problem / context

Default-on shipped calibrated at 0/61 — but rule-only (--provider mock, VECTOR_ENABLED=disabled). Under vector auto, 56/75 non-closeout smoke cases fall back to full schema and 44 have structural_score=1.0 but band=low: correct, structurally-complete queries dumped to full schema, discarding the ~65–75% context-reduction win.

Root cause: _match_strength conflates scales — lexical (0–30, ÷30) vs hybrid/vector (~0–1, used as-is). A strong hybrid recall ~0.33 reads as weak → 0.5·0.33 + 0.5·1.0 = 0.665 < 0.70 → low → expand → no gain → full-schema fallback. Threshold 0.70 was tuned on the lexical scale.

2. Goals

In scope: explicit coverage_match_strength ∈ [0,1] on both retrieval paths; scorer consumes it (legacy heuristic as absent-fallback); recalibration with vector ON incl. non-VQ phrasings; regression fixtures.

Out of scope: changing structural_score, the blend, expansion, fallback control flow, the empty invariant, rule/vector recall themselves, or adding LLM.

3. Proposed approach

Signal contract

retrieve_metadata_assets returns top-level coverage_match_strength ∈ [0,1] on both paths: the hybrid merge derives it from its own _vector_score/lexical confidence; the rule-only path normalizes its lexical top — both to the same scale, so the number reflects match quality, not channel.

Scorer change (minimal)

score_coverage uses coverage_match_strength when present, else the legacy heuristic. Everything else — blend, threshold, structural, expansion, fallback — unchanged.

Recalibration protocol

Sweep with VECTOR_ENABLED=auto on a corpus incl. non-VQ phrasings; re-derive threshold (+weights if needed); gate on recovery + 0 regression in the vector-active config; re-enable default-on only if it clears.
