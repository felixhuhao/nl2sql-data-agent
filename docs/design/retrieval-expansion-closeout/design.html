Digest

Bottom line — approve this if you agree that: flipping the expansion flags on should be gated by recovery-first / zero-regression calibration against purpose-built incomplete-recall cases, and a small additive CH set + parity anchors + a hard CH-up closeout gate proves datasource-agnosticism without running every case on ClickHouse.

Change: Close out retrieval-recall-expansion: build the incomplete-recall cases that trigger the new paths, calibrate threshold/weights defensibly, and restructure the eval harness so ClickHouse validation is cheap but honest.

Decisions (decision — why — rejected):

  • (A) Incomplete-recall case contract — each case scores band=low pre-expansion and isolates one archetype (missing-dimension / missing-join-path / dangling-no-fact). Rejected: ad-hoc cases (untriggerable, non-distinct).
  • (B) Recovery-first under hard zero-regression — maximize recovery subject to no high-confidence regression; matches feature intent, simplest to defend. Rejected: balanced (arbitrary weighting), precision-first (under-recovers).
  • (B) Single-threshold tuning · fixed weight prior · existing corpus as large-N regression holdout · dark→canary telemetry — removes the overfit surface at N≈12. Rejected: holdout split (noise at N≈12), both (false rigor).
  • (C) Additive targeted CH set + parity anchors + runner-enforced CH-up closeout gate — cheap CH smoke, still proves agnosticism, turns the silent-skip gotcha into a hard fail. Rejected: clean partition (loses parity), status-quo (skips masked green).

Risks / watch:

  • Recover-vs-fallback cases must be labelled and asserted distinctly.
  • Parity-anchor divergence is a real bug signal, not flakiness.
  • Calibrated numbers stay provisional until canary telemetry confirms.

Open questions:

  • Exact threshold + weight-prior ratio (pinned during calibration); parity-anchor count (2 vs 3).

Drill down: full design in design.md · tasks in tasks.md.

1. Problem / context

retrieval-recall-expansion shipped dark and uncalibrated — flags off, guessed threshold/weights, and validation only hit a band=high case so expansion/fallback have zero e2e evidence and nothing to calibrate against. ClickHouse validation was skipped (CH down), which the project's own gotcha warns masks failures behind green DuckDB smoke. This design closes those gaps via three design-worthy decisions (A/B/C); the rest is execution in tasks.md.

2. Goals

In scope: (A) incomplete-recall case validity contract; (B) calibration methodology (objective + anti-overfit) that flips flags on; (C) datasource-partitioned harness (tagging, runner selection, targeted CH set, parity anchors, CH-up closeout gate).

Out of scope — self-explanatory (tasks.md): e2e expansion/fallback validation cases; flags-off/on context-size delta; status + SPEC hygiene.

Non-goals: changing the coverage/expansion algorithm; LLM retrieval; new connectors.

3. Key decisions

(A) Incomplete-recall case contract — light

archetyperecall shapeexpected path
missing_dimensionfact recalled; needed dim absentexpansion recovers (expanded=true, post high)
missing_join_pathtwo tables, no connecting edgedangling → recover if 1-hop edge exists, else fallback
dangling_no_factnon-fact only, no metric intentstays low → fallback (fallback_used=true)

Each case carries expected.coverage (pre/post band, expanded, fallback_used) so the runner asserts the path taken. This is the shared foundation for B and the e2e cases.

(B) Calibration methodology — core

Objective: maximize recovery over missing_dimension/missing_join_path subject to zero regression on high-confidence cases (band stays high, context size unchanged).

Anti-overfit (N≈12): (1) fix weight prior w_struct>w_strength, constants for MAX_TABLES/budget; (2) tune the single threshold; (3) bind zero-regression to the 51+ existing high-confidence cases (large-N holdout); (4) dark→canary→tune via emitted band/expanded/fallback_used telemetry.

Reporting: per threshold — recovery rate · regression count (must be 0) · context-size delta. Flags flip on only at target recovery + 0 regression; chosen numbers written back to the sibling design.

(C) Datasource-partitioned harness — structural

  • Compatibility: legacy scalar datasource: X (instance name, e.g. clickhouse_ecommerce) normalizes to [X] — zero migration; plural datasources: [X, Y] for parity cases; both keys → error; neither → [duckdb_ecommerce].
  • Runner: _case_datasource → _case_datasources; run per available listed datasource; unavailable → explicit SKIP, never a pass.
  • CH set: small, targeted — CH OLAP metadata through coverage + the three new paths on CH-synced metadata (~4-5 cases).
  • Parity anchors: 2-3 [duckdb_ecommerce, clickhouse_ecommerce] cases; assert band matches across datasources.
  • Closeout gate: --require-clickhouse-style mode fails if a CH case is SKIPPED due to CH down — converts the skip gotcha into a hard failure.
