# NL2SQL Phase 2.5 设计文档

> 日期: 2026-05-30
> 状态: 已完成
> 前置: Phase 2 DB-backed 语义层已完成
> 范围: 语义资产管理 API + Admin UI（可选阶段）

## 1. 关键决策记录

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 管理方式 | REST CRUD API + 前端 Admin 页面 | seed.py 只负责初始化，运行时管理走 API |
| Admin UI 布局 | Tab 式单页面 | 数据量 <100 行，5 个 Tab 以内，紧凑够用 |
| 前端导航 | App 内部 Tab 切换 Chat/Admin | 当前前端未引入 vue-router，Phase 2.5 不新增路由依赖 |
| Relationship 编辑 | 只改元数据字段，人工确认写成 overlay | 表/列映射由 sync 管理；sync 当前只保留 overlay 关系 |
| 校验策略 | 后端为主，前端只做非空 | 避免前后端校验逻辑重复 |
| Analysis Space | 单例模式，只 PUT 不 POST | 当前只有一个 active space |
| Alias | 无启停，直接删除 | 别名是轻量映射，存在即生效，不存在即无效 |
| seed.py 行为 | 不变，reset=True 仍会覆盖用户编辑 | Admin 和 seed 职责分离，UI 中需提示 |

## 2. Phase 2.5 核心能力

1. **Metrics CRUD** — 列表、新增、编辑（label/expression/description/维度）、启停
2. **Column Aliases CRUD** — 列表、新增、删除
3. **Verified Queries CRUD** — 列表、新增、编辑（question/sql/tags）、启停
4. **Analysis Space 编辑** — 表白名单、指标白名单、allowed operations
5. **Relationships 编辑** — confidence、fanout_risk、source、description
6. **失效资产校验** — 检测引用断裂（表不存在、字段不存在、expression 引用失效）
7. **Admin UI** — Tab 式单页面，表格 + 侧边编辑面板

## 4. API 设计

### 4.1 Metrics CRUD

```
GET    /api/metadata/metrics                 # 列表，支持 ?enabled=true 过滤
POST   /api/metadata/metrics                 # 新增
PUT    /api/metadata/metrics/{name}          # 编辑
PATCH  /api/metadata/metrics/{name}/toggle   # 启停切换
```

**Pydantic 模型：**

```python
class MetricCreate(BaseModel):
    name: str
    label: str
    expression: str
    description: str | None = None
    default_time_column: str | None = None
    allowed_dimensions: list[str] | None = None

class MetricUpdate(BaseModel):
    label: str | None = None
    expression: str | None = None
    description: str | None = None
    default_time_column: str | None = None
    allowed_dimensions: list[str] | None = None
    enabled: bool | None = None

class MetricResponse(BaseModel):
    name: str
    label: str
    expression: str
    description: str | None
    default_time_column: str | None
    allowed_dimensions: list[str] | None
    enabled: bool
```

**校验：**
- `name` 唯一，冲突返回 409
- `expression` 中的 qualified columns 必须存在，例如 `fact_orders.payment_amount`
- `default_time_column` 如存在，必须是有效的 `table.column`
- `allowed_dimensions` 先按字符串保存，不校验维度枚举；后续如果引入维度资产表再收紧

### 4.2 Column Aliases CRUD

```
GET    /api/metadata/aliases                 # 列表，支持 ?table_name= 过滤
POST   /api/metadata/aliases                 # 新增
DELETE /api/metadata/aliases/{id}            # 删除
```

**Pydantic 模型：**

```python
class AliasCreate(BaseModel):
    table_name: str
    column_name: str
    alias: str

class AliasResponse(BaseModel):
    id: int
    table_name: str
    column_name: str
    alias: str
```

**校验：**
- `(table_name, column_name, alias)` 唯一，冲突返回 409
- `table_name` 必须在 `meta_tables` 中存在
- `(table_name, column_name)` 必须在 `meta_columns` 中存在（通过 table → columns 关联查询）

### 4.3 Verified Queries CRUD

```
GET    /api/metadata/verified-queries                    # 已有，增加 ?enabled=true 过滤
POST   /api/metadata/verified-queries                    # 新增
PUT    /api/metadata/verified-queries/{query_id}         # 编辑
PATCH  /api/metadata/verified-queries/{query_id}/toggle  # 启停切换
```

**Pydantic 模型：**

```python
class VerifiedQueryCreate(BaseModel):
    query_id: str
    question: str
    sql: str
    tags: list[str] | None = None
    verified_by: str = "user"

class VerifiedQueryUpdate(BaseModel):
    question: str | None = None
    sql: str | None = None
    tags: list[str] | None = None
    enabled: bool | None = None
```

**校验：**
- `query_id` 唯一，冲突返回 409
- `sql` 必须可被 sqlglot 解析（try parse，失败返回 422）
- `sql` 必须通过 SQL Guard：SELECT-only、Analysis Space 白名单、字段 scope、禁外部读取函数
- 保存时使用当前 DB-backed Guard scope；如果 Analysis Space 以后变化，`GET /api/metadata/validate` 负责暴露失效 query

### 4.4 Analysis Space 编辑

```
GET  /api/metadata/analysis-space    # 已有
PUT  /api/metadata/analysis-space    # 编辑（单例更新）
```

**Pydantic 模型：**

```python
class AnalysisSpaceUpdate(BaseModel):
    tables: list[str] | None = None
    enabled_metrics: list[str] | None = None
    allowed_operations: list[str] | None = None
```

**校验：**
- `tables` 中的每个表名必须在 `meta_tables` 中存在
- `enabled_metrics` 中的每个指标名必须在 `meta_metrics` 中存在
- `allowed_operations` 只允许 `["select"]` 或包含单个 `"select"`；Phase 2.5 不支持写入其他操作

### 4.5 Relationships 编辑

```
GET  /api/metadata/relationships                 # 列表
PUT  /api/metadata/relationships/{id}            # 编辑元数据
```

**Pydantic 模型：**

```python
class RelationshipUpdate(BaseModel):
    confidence: float | None = None        # [0, 1]
    fanout_risk: str | None = None         # low / medium / high
    source: str | None = None              # inferred / overlay
    description: str | None = None
```

**校验：**
- `confidence` 范围 [0, 1]
- `fanout_risk` 只允许 low / medium / high
- `source` 只允许 inferred / overlay
- 用户人工确认关系时写成 `overlay`，不要写 `confirmed`
- 不允许修改 source_table / source_column / target_table / target_column

说明：`sync_metadata()` 当前只把 `source == "overlay"` 的关系作为人工覆盖保留。若引入 `confirmed`，必须同步修改 sync 逻辑，否则下次 sync 会覆盖或删除该关系。

### 4.6 失效资产校验

```
GET  /api/metadata/validate    # 返回所有失效资产
```

**校验项：**

| 资产类型 | 校验内容 |
|---------|---------|
| Metric | expression / default_time_column 中的 qualified columns 是否存在于 meta_tables / meta_columns |
| Alias | table_name + column_name 是否存在于 meta_columns |
| Verified Query | sql 是否通过 SQL Guard，表和字段是否仍在 analysis space 白名单内 |
| Analysis Space | tables 是否存在于 meta_tables，enabled_metrics 是否存在于 meta_metrics，allowed_operations 是否只包含 select |
| Relationship | source_table / target_table 是否存在于 meta_tables，列是否存在 |

**响应格式（实际实现）：**

```json
{
  "ok": false,
  "issues": [
    {
      "severity": "error",
      "asset_type": "metric",
      "asset_id": "aov",
      "field": "expression",
      "message": "Column not found: fact_orders.nonexistent_col"
    }
  ]
}
```

字段取舍：

- `ok` 替代设计初稿中的 `valid`，与后端返回风格一致。
- `asset_id` 替代 `asset_name`，因为 alias 等资产使用数字 id 更准确。
- `message` 替代 `issue`，表达更清晰。
- `severity` 预留分级能力；Phase 2.5 当前只返回 `error`。

## 6. Admin UI 设计

### 6.1 路由

Phase 2.5 不引入 `vue-router`。在现有 `App.vue` 内部增加 `activeView` 状态：

```text
activeView = "chat" | "admin"
```

顶部导航栏右侧：`[问数] [管理]`。点击后在同一个页面内切换 Chat/Admin，不改变 URL。

### 6.3 Tab 设计

**指标 Tab：**
- 表格列：名称、标签、表达式（截断）、默认时间列、状态（switch）、操作（编辑按钮）
- 新增按钮 → 侧边面板空白表单
- 编辑按钮 → 侧边面板预填表单
- switch 切换 → 即时调 PATCH toggle API
- 表达式过长时用 `<details>` 折叠

**别名 Tab：**
- 表格列：表名、列名、别名、操作（删除按钮）
- 顶部下拉框过滤：按表名过滤
- 新增按钮 → 侧边面板（表名下拉、列名下拉根据表名联动、别名输入框）
- 删除 → 确认弹窗 → 调 DELETE API

**验证查询 Tab：**
- 表格列：ID、问题、SQL（折叠）、标签（chips）、验证者、状态（switch）、操作（编辑）
- SQL 用 `<pre>` 块 + 折叠展示
- 新增/编辑 → 侧边面板

**分析空间 Tab：**
- 表单式布局（不是表格），直接编辑
- 表白名单：checkbox 多选（从 meta_tables 读取）
- 指标白名单：checkbox 多选（从 meta_metrics 读取）
- 允许操作：checkbox 多选（select）
- 底部保存按钮 → 调 PUT API

**关系 Tab：**
- 只读表格 + 编辑按钮
- 表格列：源表→列、目标表→列、类型、来源、置信度、扇出风险、操作
- 编辑按钮 → 侧边面板（只显示 confidence / fanout_risk / source / description 四个字段）

### 6.4 交互原则

- 表格不分页（数据量 <100 行）
- 编辑用侧边滑入面板（宽度 ~400px），不用弹窗
- 删除需确认（`confirm()` 即可）
- 启停用 switch 组件，onChange 直接调 API
- 保存时后端校验，前端只做基础非空校验
- 错误提示用 inline message（表格上方红色提示条）
- 保存成功后自动刷新表格数据

### 6.5 新建文件

```
frontend/src/
  Admin.vue                      # Admin 主页面（Tab 容器 + 表格 + 侧边编辑面板）
  api/
    admin.ts                     # Admin API 调用函数
```

实际实现没有拆 `components/admin/*`。Phase 2.5 的 UI 规模仍小，单文件能减少组件边界和状态传递；后续如果 Admin 页面继续膨胀，再拆 Tab 组件。

## 8. 集成测试场景

1. 新增别名 "成交金额" → `GET /api/metadata/retrieve?question=成交金额` 命中该别名对应的列
2. 禁用 metric `aov` → `build_schema_context()` 不再包含 aov 指标定义
3. 编辑 analysis space 移除 `dim_channels` → SQL Guard 拒绝访问 dim_channels 的 SQL
4. 编辑 relationship confidence 为 1.0 → explainability 输出反映新 confidence
5. 新增 verified query → 检索 API 命中该 query

## 9. 验收标准

- 可以不用改代码就新增一个字段别名，并让检索 API 命中它
- 可以不用改代码就禁用一个 metric，并让 Agent 不再使用它
- 修改 analysis space 后，SQL Guard 和 retrieval 行为同步变化
- 所有写接口都有基础引用校验和测试
- Admin UI 可正常管理所有 5 类语义资产
- 失效资产校验 API 可检测引用断裂
- 现有 smoke eval（15 cases）不回归
- 现有 pytest 不回归

## 10. 已知取舍

- seed.py `reset=True` 仍会覆盖用户通过 Admin 做的编辑。如果用户需要保留编辑，sync 时不要传 reset。Admin UI 中 sync 按钮旁应有提示。
- Alias 没有 enabled 字段，只做新增/删除。如果需要暂时停用某个别名，删除后重新添加即可。
- Analysis Space 当前是单例。如果需要多 space 支持，需要改 seed 逻辑、retrieval 逻辑和 SQL Guard scope，属于较大变更。
- 前端不做复杂表单校验，依赖后端 422 响应展示错误信息。
- 不做操作审计日志。如果需要追踪谁改了什么，后续加 updated_by / updated_at 字段。
